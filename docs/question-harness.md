# 回答运行框架（Harness）

`question_harness.mjs` 统一管理一次回答的模型路由、搜索规划、搜索工具和最终回答。它复用现有 OpenAI-compatible 调用，API Key 与订阅账号使用同一条执行流程，没有新增框架依赖或配置项。

## 执行流程

1. 克隆并冻结提问、视频时间、视频上下文、历史问答与记忆，避免异步等待期间数据变化。截图晚于提问时间或早于提问时间超过 0.5 秒时舍弃。模型请求继续通过现有规则过滤未播放的文字、问答与摘要。
2. 解析本次选择的模型路由。常见的“解释当前片段”“整理当前片段笔记”等问题直接进入回答；涉及外部资料或最新信息的问题仍交给搜索规划器判断。
3. 如需搜索，规划器最多生成两个查询，通过现有公共搜索工具取回摘要。外部摘要仅作为用户数据附加，系统指令要求忽略其中的指令，并继续遵守防剧透范围。
4. 调用所选模型生成最终回答，返回回答、搜索来源和脱敏运行轨迹。

联网关闭或本地解释命中快捷规则时只调用一次模型。其余问题最多一次规划、一次回答。规划器拒绝明确的联网请求、输出无效 JSON，或搜索失败时，保留最后一次回答的预算，并明确提示本次未完成联网核实。

## 预算与停止

| 范围 | 上限 |
| --- | --- |
| 回答阶段总耗时 | 150 秒 |
| 模型路由解析 | 15 秒 |
| 搜索规划 | 20 秒 |
| 单个搜索查询 | 40 秒 |
| 最终回答 | 90 秒 |
| 模型调用次数 | 2 次，规划时为回答保留 1 次 |
| 搜索查询数 | 2 个 |

各步骤受剩余总时限约束，时限不会逐步累加突破 150 秒。搜索工具沿用 Bing → DuckDuckGo → Wikipedia 的顺序降级；一个逻辑查询最多产生三次搜索 HTTP 请求，因此两次查询最多六次搜索请求。缓存命中不产生搜索 HTTP 请求。模型 POST 不自动重试，避免重复计费。

预算按每次提问重新计算，不限制同一视频的提问次数，也不会因为课程有一两小时就用完预算。[长课程记忆](course-memory.md) 负责从完整缓存中提取当前问题需要的内容。

开始回答后，发送按钮变为“停止回答”。停止会中断本次规划、搜索或回答的 fetch 信号，阻止继续执行搜索降级和后续模型调用，并丢弃竞态下已经返回的回答。未切换视频时恢复原问题，便于修改后重发。模型服务已完成的工作仍可能计费，浏览器取消无法撤销服务端已经完成的推理。

150 秒与两次模型调用的预算只覆盖上述回答阶段。此前的视频文本准备、截图和长期记忆整理有自己的流程；记忆整理仍可能额外调用一次模型。等待视频文本时沿用原有的“取消”功能。停止本次回答不会停止从 00:00 开始的后台整段转写与缓存。模型配置解析中的 Native Messaging 读取可在本次流程中取消等待，底层读取可能稍后自行结束。

## 脱敏轨迹

每条已完成问答的本地历史可保存 `runTrace`；最近一次运行（包括失败）的轨迹保留在侧栏 `state.lastRunTrace`，可在侧栏开发者工具控制台查看。当前没有独立诊断面板，也不向远程分析服务上传轨迹。

轨迹仅包含随机运行 ID、固定范围 `answer`、状态、搜索结果状态、各步骤耗时、模型调用数、逻辑查询数和固定错误码。不包含 API Key、账号信息、模型请求正文、视频标题、转写文本、搜索查询、来源 URL 或上游错误原文。轨迹不写入 Markdown 学习笔记。

## 可重复评测

```bash
npm run test:harness
npm run eval:harness
npm test
```

`test:harness` 验证调用预算、最终回答预留、阶段与总时限、快照冻结、轨迹脱敏，以及真实后台流程到模拟 fetch 的取消信号传递；同时验证侧栏停止后的按钮恢复、原问题恢复、切换视频和竞态返回处理。

`eval:harness` 逐项回放 `scripts/evals/question-cases.json`，输出通过情况。固定场景包括快捷解释、关闭联网、主动搜索、最新信息、无效规划、搜索故障、查询上限、不可信来源、限流、防剧透、未来截图和快照变更。每次都检查模型调用数、逻辑查询数、搜索状态与提示、未播放内容过滤和轨迹字段。

这组评测完全离线：模型和搜索响应均由固定数据模拟，不读取账号凭证、不调用网络，不衡量模型回答的事实准确率或语言质量。真实模型、真实字幕和真实音频的端到端测试需要另行执行。新增回归场景时先加入固定用例与预期，再修改运行逻辑，避免把一次手工成功当作稳定性证明。
