# 长课程记忆

一小时、两小时课程的可用上下文由两种记忆共同提供：课程原文记忆负责找回讲过的内容，对话记忆负责延续用户已经问过的问题。每次回答阶段的两次模型调用上限不会限制整段视频的提问次数。

## 课程原文记忆

后台继续从 00:00 获取整段字幕或音频转写，并复用完整文本缓存。回答时先按提问快照时间过滤，未结束的字幕片段和后续内容不进入索引。已播放文本不超过 12000 字符时直接提供全文。

超过此长度后，`course_memory.mjs` 组合以下三部分：

| 部分 | 用途 | 原文字符预算 |
| --- | --- | --- |
| 当前窗口 | 理解眼前讲解 | 3000 |
| 相关原文 | 找回早期定义、公式或例子 | 4800，最多 8 块 |
| 课程分块索引 | 提供已播放课程的整体线索 | 3600 |

预算只统计原文字符，不包含时间戳、标题、历史问答、系统指令和其他提示词；它不是厂商的精确 token 计数或整个模型输入的 token 上限。

一小时课程约 12 个、两小时课程约 24 个五分钟时间块。每块保留开头、中间、结尾及块内词语较集中的代表性原文节选，并保留时间戳。超过三小时后扩大时间块，最多 36 块，避免随课程时长无限增加模型输入。原文有空白的时间段不生成虚构内容。这些时间块是按时间划分的索引，不是自动识别的课程章节，也不是完整章节摘要。

检索优先匹配问题中的术语，按词语在已播放文本中的分布加权，并在必要时参考当前讲解的词语。支持 `10:00`、`01:20:00`、`第10分钟`、`1小时20分钟`、`10分钟前` 等时间定位。概览问题兼顾已播放范围各处的证据；具体问题优先找相关原文。因此某个知识点即使此前没有被提问，也可以从课程缓存找回。

所有索引和检索都在本地进行，不新增模型调用、搜索服务、向量数据库或用户配置项。关掉侧栏后完整文本仍由原有缓存保留；再次打开时从缓存重建索引，不要求重新提问或重新识别。浏览器完整文本缓存沿用原有大小与数量限制，被淘汰的内容需从本地视频文本服务缓存或视频字幕重新取得。索引不重复存入每条问答记录。

## 对话记忆

原有策略继续生效：最近 6 轮问答保持原文，较早问答每累计 3 轮触发一次滚动摘要（单次最多 8 轮），并检索相关旧问答。聊天历史和摘要按视频隔离保存。摘要更新可能额外调用一次模型，独立于回答阶段的预算；课程分块索引本身不产生模型调用。

## 防剧透与局限

课程索引只从截至提问时间已结束的原文构建。回退后重新生成更早范围的索引；在最终模型请求处再次检查时间范围，拒绝使用后来时间点生成的整份索引。历史问答及聊天摘要同样按 `contextEnd` / `summaryThrough` 过滤。

有限的上下文无法容纳两小时课程的所有细节。当前检索基于词语和时间匹配；同义词、代词指代和跨多个片段的长证明仍可能找不全。提示词明确说明索引只是节选，要求具体问题优先依据原文，证据不足时说明缺失。不要把固定场景通过当成任意长课程都能准确回答的保证。

## 验证

```bash
npm run test:course-memory
npm test
```

离线测试包含 1 小时、2 小时与 12 小时的模拟课程文本：验证所有已播放时间块都有索引、找回一小时前未被提问的知识点、绝对和相对时间定位、回退防剧透、缓存重新加载、渐进转写和字符预算。还验证输出不修改完整文本缓存。它们不调用网络，不等同于真实两小时音频转写或模型回答准确率测试。
